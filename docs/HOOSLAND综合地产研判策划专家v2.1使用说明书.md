# HOOSLAND 综合地产研判策划专家 v2.1 使用说明书

**适用对象：** 初级至中级地产从业者、项目策划、投资研判、营销、产品、运营及管理人员  
**版本：** 2.1.0  
**作者：** HOOSLAND  
**更新日期：** 2026年7月29日

> 你不需要先学会复杂的地产术语。只要告诉它“是什么项目、现在做到哪一步、最想解决什么”，它会帮助你把问题拆开，逐步完成资料收集、研究、测算、策略和报告。

## 一、它是什么

这是一个面向房地产项目的综合研判与策划 Skill 套件，由 **1个总控 + 5个专业模块**组成。

总控像项目负责人：识别你的问题、安排研究顺序、管理项目状态、检查证据和测算是否可靠。专业模块分别处理研究、产品、营销、社群和微信资料。

| 模块 | 通俗解释 | 主要工作 |
|---|---|---|
| 综合地产总控 | 项目负责人 | 跨模块推进、状态管理、证据检查、综合报告 |
| 地产研判研究 | 研究员 | 城市、板块、土地、规划、市场、竞品、客群 |
| 产品与产策 | 产品策划师 | 定位、面积段、户配、价格、货值、开发节奏 |
| 品牌与营销 | 营销策划师 | 故事线、传播主张、内容、活动、销售话术 |
| 社群运营 | 客户运营负责人 | 私域、业主社群、活动、老带新、NPS |
| 微信资料入口 | 资料整理员 | 抓取微信文章、转换格式、纳入研究证据 |

## 二、它能做什么

### 1. 土地与投资研判

- 核对地块范围、用途、容积率、计容、限高、配建和出让条件；
- 区分片区总规、一期出让、单个宗地和住宅子地块；
- 识别学校、道路、地铁保护区、自持、代建、权益物业等开发约束；
- 研究板块供需、成交、存量、未来供应和政策风险；
- 形成机会、风险、进入条件和待验证清单。

适合这样问：

```text
帮我快速判断广州XX地块值不值得继续研究，重点看规划、市场容量和主要风险。
```

### 2. 市场、竞品与客群研究

- 建立直接竞品、替代竞品、错位项目和待观察项目清单；
- 区分报价、备案价和真实成交价；
- 比较面积、总价、产品、去化、推售时间和客户来源；
- 判断客户从哪里来、为什么买、能承担多少总价；
- 研究二手房、租赁和跨板块替代关系。

适合这样问：

```text
帮我研究这个项目的竞品和客群。我只有项目名称，请先从公开资料开始，并告诉我还缺什么。
```

### 3. 产品定位与产策

- 形成一句话产品定位；
- 设计主力与次主力面积段；
- 建立“面积—总价—客群—竞品”矩阵；
- 推导户配、约套数、价格梯度和货值情景；
- 分析户型功能、动线、采光、收纳、梯户比和私密性；
- 安排首开、续销和旗舰产品节奏。

适合这样问：

```text
我们想做120㎡、143㎡和180㎡三种产品。请判断对应客群、总价风险和建议户配。
```

### 4. 品牌故事与营销

- 提炼项目的真实利益点和客户矛盾；
- 形成品牌命题、故事线、章节、Slogan和视觉方向；
- 制定首开前、首开期、续销期营销节奏；
- 编写沙盘、样板间、异议处理和逼定话术；
- 生成朋友圈、小红书、短视频、直播和媒体选题；
- 设计发布会、开放日、品鉴会和圈层活动。

适合这样问：

```text
基于现有产品定位，帮我形成一条不空泛的品牌故事线和首开传播主张。
```

### 5. 社群与长期客户运营

- 区分泛意向、强意向、已认购、业主和主理人；
- 设计社群定位、内容、活动、空间和运营机制；
- 制定90天试运行方案；
- 设计老带新、主理人和业主共创机制；
- 建立活跃率、到场率、推荐转化率和NPS指标；
- 评估人力、预算、隐私和长期运营风险。

适合这样问：

```text
项目有3个业主群、约800人，请设计一个90天社群运营和老带新试运行方案。
```

### 6. 微信文章与资料入口

- 将微信公众号文章保存为Markdown、HTML、文本、JSON或Excel；
- 保留标题、作者、发布日期、原链接和抓取日期；
- 提取文章中的事实、观点、数据和待核验线索；
- 将微信文章纳入项目来源账本；
- 批量整理多篇文章。

你只需发送微信文章链接并说明用途：

```text
把这篇微信文章作为XX项目的研究资料归档，并提取其中需要核验的数据：链接……
```

普通地产研究不会自动调用微信入口；只有提供微信链接或明确要求转换时才会启用。

## 三、最简单的使用方法

### 方法一：只说项目和问题

这是最推荐的入门方式：

```text
帮我研究【项目名称】。
项目在【城市/板块】，目前处于【拿地前/已拿地/定位/首开/在售/复盘】阶段。
我最想解决的问题是【问题】。
```

例如：

```text
帮我研究广州天河某住宅项目。项目已经拿地，正在做定位。我最想知道应该做多大户型，以及首开怎么安排。
```

系统会先复用你已经提供的信息，最多补问3个真正影响结论的问题，然后开始做分析，不会先发一大套专业问卷。

### 方法二：直接上传资料

你可以上传或指定：

- 土地出让公告、规划条件、规划图、总平面图；
- 市场月报、竞品表、成交表、客户访谈；
- 户型图、产品方案、成本测算、销售日报；
- PDF、Word、Excel、图片、网页链接或微信链接。

示例：

```text
这些是地块规划条件和竞品表。请先核对范围和数据口径，再形成产品定位初稿。
```

### 方法三：指定最终交付

```text
基于现有资料直接形成一份管理层报告，输出Markdown和HTML。资料不足的地方不要猜，列为待验证项。
```

支持按需要形成Markdown、HTML、Word、PPT、PDF、Excel或数据看板。只有实际生成并检查后的文件才会被标记为已完成。

## 四、系统会怎样推进项目

### 第一步：确认项目身份

系统会识别六项基础信息：

| 信息 | 普通话解释 | 示例 |
|---|---|---|
| 项目名称 | 正在研究哪个项目 | 广州XX项目 |
| 研究范围 | 是片区、一期还是某个地块 | 一期住宅地块 |
| 项目阶段 | 项目现在进行到哪里 | 投前、定位、首开、在售 |
| 经营目标 | 这次优先保什么 | 保利润、保现金流、保去化、保品牌 |
| 截止日期 | 数据看到哪一天 | 2026-07-29 |
| 研究深度 | 这次要多深入 | 快速、标准、审计 |

### 第二步：区分事实、推导和建议

你会在报告中看到以下标签：

| 标签 | 含义 | 例子 |
|---|---|---|
| FACT-A | 来自政府、法定文件或正式系统的事实 | 地块计容面积 |
| FACT-B | 来自企业正式披露或权威研究的事实 | 企业销售公告 |
| FACT-C | 来自媒体、平台、公众号或销售口径 | 平台报价 |
| DERIVED | 根据事实计算得到 | 两个住宅地块面积相加 |
| INFERENCE | 基于证据做出的分析判断 | 高总价会缩小客户池 |
| HYPOTHESIS | 尚待验证的策略假设 | 建议主力做143㎡ |
| RECOMMENDATION | 在当前证据下给出的动作建议 | 首开先推中间面积段 |

这些标签的作用是防止把“宣传说法”当成事实，也防止把“初步想法”写成确定结论。

### 第三步：判断可以算到什么程度

| 等级 | 你提供的资料 | 系统能给出的结果 |
|---|---|---|
| L0 方向级 | 公开规划、新闻或基础片区资料 | 机会、约束、方向、待验证清单 |
| L1 假设级 | 宗地指标、竞品成交、客户支付信息 | 面积、户配、价格、去化情景 |
| L2 决策级 | L1资料 + 可售率、成本、税费、工程和经营约束 | 货值、利润、现金流及决策建议 |

如果资料只够L0，系统不会假装算出准确利润；它会完成能完成的内容，并告诉你还缺哪些数据。

### 第四步：每轮推进一个结果

每轮对话通常会给出：

1. 已确认的信息；
2. 这些信息对项目的影响；
3. 仍需核实的缺口；
4. 本轮完成的范围表、竞品表、测算或结论；
5. 若任务未结束，再给2–4个下一步动作。

你可以回复编号，例如“1+2”；也可以直接输入自己的想法，例如“主力户型我想改成140㎡”。系统会说明这个改动影响哪些客群、总价、套数和风险，再继续推进。

## 五、三种研究深度怎么选

### 快速模式

适合领导临时提问、项目初筛、短时间判断。

```text
用快速模式判断这个地块，先给我方向、核心风险和下一步资料清单。
```

输出重点：一句话判断、3–5个关键事实、主要风险、是否值得继续研究。

### 标准模式

适合定位会、产策会、竞品研究和正式方案初稿。

```text
用标准模式完成市场、竞品、客群和产品定位，并形成可复核报告。
```

输出重点：范围、官方规划、竞品交叉验证、客群支付、产品假设、敏感性和风险。

### 审计模式

适合拿地、重大调价、投委会或高风险管理层决策。

```text
用审计模式研究该项目。所有关键数字建立来源账本、矛盾记录和计算底稿。
```

输出重点：逐项来源、证据等级、矛盾处理、公式底稿、复核状态和可决策条件。

## 六、不同项目阶段应该怎么用

### 1. 拿地前

```text
项目准备参与拿地。请按标准模式完成法定条件、市场容量、竞品、支付边界和主要风险研判，并给出继续/谨慎/停止建议。
```

建议准备：出让公告、规划条件、红线图、板块成交、未来供应和企业投资边界。

### 2. 已拿地或定位阶段

```text
项目已经拿地，当前要确定产品。请从地块约束、竞品成交和客户支付出发，形成面积—总价—户配矩阵。
```

建议准备：宗地指标、总平面草案、竞品成交、客户访谈、可售率和初步成本。

### 3. 首开准备

```text
项目准备首开，请检查首开货量、面积段、价格梯度、客户蓄水和竞品动态，形成30天首开策略。
```

建议准备：货量、楼栋、销售目标、蓄客表、价格表、渠道计划和关键配套时序。

### 4. 在售诊断

```text
项目最近去化下降。请按到访—认筹—成交漏斗诊断问题，区分产品、价格、竞品、渠道和话术原因。
```

建议准备：近8–12周来访、认筹、成交、退订、渠道、客户流失和竞品变化。

### 5. 项目复盘

```text
请复盘本项目从定位到销售的假设偏差，找出哪些经验可以复制、哪些需要停止。
```

建议准备：原定位报告、推售记录、成交客户、未成交客户、价格动作、客诉和渠道投入。

## 七、可直接复制的常用指令

### 综合研判

```text
帮我对【项目】做一次标准模式综合研判，覆盖土地、市场、竞品、客群、产品、价格、营销和风险。先利用公开资料推进，缺口单独列出。
```

### 竞品研究

```text
请为【项目】建立竞品表，区分直接竞品、替代竞品、错位项目和待观察项目。价格必须区分报价、备案和成交。
```

### 客群研究

```text
请把【项目】的客户分成地缘、辐射和外溢三层，并说明每类客户的家庭结构、购买动机、总价边界和替代选择。
```

### 产品定位

```text
基于现有土地、市场和客群资料，形成产品定位、主力面积、户配、总价区间和产品失效信号。证据不足的地方标为假设。
```

### 户型评审

```text
评审这张户型图，重点检查功能效率、动静分区、公私分区、家政动线、采光通风、收纳、梯户比和私密性。
```

### 价格与货值

```text
按保守、基准、乐观三种情景测算价格和住宅货值。先说明当前是L0、L1还是L2，所有假设单独列出。
```

### 品牌故事

```text
把这些零散卖点整理成客户能理解的品牌故事线，区分真实事实、分析意义、创意表达和需要审批的承诺。
```

### 销售话术

```text
基于项目定位，生成接待、沙盘、样板间、异议处理和逼定五个环节的话术，不使用空泛套话。
```

### 社群运营

```text
为项目设计90天社群试运行，区分强意向、已认购和业主，写清活动、人员、预算、指标和复盘方式。
```

### 微信资料

```text
把以下微信文章作为【项目】研究资料归档为Markdown和JSON，提取事实、作者观点、数据和待核验线索：链接……
```

### 形成报告

```text
根据当前已经完成的研究形成管理层报告。必须包含一句话结论、主矛盾、机会、风险、策略、失效信号、来源和待决策事项。
```

## 八、怎样提供资料效果最好

不需要一次给齐，可以边做边补。资料越接近原始文件，结论越可靠。

优先顺序：

1. 政府规划、土地出让、成交和正式批复；
2. 企业正式台账、成交、成本和客户数据；
3. 权威研究机构与正式市场报告；
4. 媒体、平台、公众号和销售口径；
5. 匿名转述或无日期截图只作为调查线索。

提供表格时，尽量保留项目名、日期、面积、单位、价格口径和来源。客户数据应删除姓名、手机号、身份证等不必要的个人信息。

## 九、系统不会做什么

- 不会把规划中的地铁、学校或商业写成已经建成；
- 不会把直线距离写成真实通勤时间；
- 不会把挂牌价或销售报价写成真实成交价；
- 不会把微信公众号或营销文案直接当成法定事实；
- 不会在缺少成本、税费和可售数据时输出确定性利润；
- 不会为了让报告看起来专业而伪造小数精度；
- 不代替规划、法律、财务、审计或投委会的人工复核。

## 十、常见问题

### 我完全不懂地产术语，可以使用吗？

可以。它默认按初级从业者理解能力推进，首次出现专业词会用普通话解释。你只需说明项目、阶段和问题。

### 我只知道项目名称，没有资料怎么办？

可以先说“从公开资料开始”。系统会先做L0方向性研究，并列出最值得补充的资料。

### 一定要说出模块名称吗？

不需要。直接说任务即可。单一问题会进入对应专业模块；同时涉及市场、产品和营销时，总控会统一推进。

### 如何避免研究跑偏？

开场说清楚经营目标，例如“这次优先保去化”或“领导最关心现金流”。对话中也可以随时纠正：“先暂停营销，只研究产品和价格。”

### 我回复“1+2”是什么意思？

表示同时执行上一轮给出的第1和第2个动作。你也可以不选编号，直接说自己的方案或补充资料。

### 为什么有时不给明确售价？

因为资料可能只达到L0或L1。系统会先说明证据等级，再给方向或情景，避免把未经验证的价格当成决策结论。

### 为什么同一个项目会出现多个面积数字？

可能分别代表片区总规、出让范围、计容、住宅、商业、公服、地下或可售面积。系统会为不同范围设置独立标识，不允许直接混算。

### 报告中的“可复核稿”是什么意思？

表示范围、来源和算术已经达到可以内部检查的程度，但仍缺少部分业务数据或人工审批，尚不能直接用于最终投资决策。

## 十一、推荐的第一次使用方式

复制下面这段，把方括号内容替换成你的项目：

```text
请使用综合地产研判策划专家v2.1帮助我推进项目。

项目名称：【填写】
城市/板块：【填写】
当前阶段：【拿地前/已拿地/定位/首开/在售/复盘】
核心目标：【保利润/保现金流/保去化/保品牌/暂不确定】
最想解决的问题：【用普通话描述】
```
