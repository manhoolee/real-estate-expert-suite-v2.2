# 地产报告文案编辑 v2.2

## 正式成稿标准

本 skill 的输出不是工作草稿，而是可直接提交的正式文案。文案必须严谨、准确、完整、可复核；用户与 agent 的交流、任务说明、提示、备注、工作流、制作说明、内部推理、编辑过程和质检过程一律不得出现在正文、标题、图注、脚注或结尾。

## 正文纯净门禁

最终成稿只保留读者需要的事实、分析、结论和行动。不得把对话、任务描述、提问、提示词、编辑说明、AI生成说明、内部推理、质检问题、来源台账、假设表或发布备注写进正文。来源和限制若必须出现，应改写为自然的事实边界；详细来源、假设、编辑记录和待办事项另存为附录或独立台账。

## 目标

把已经完成的分析编辑成“先结论、后证据、可复核、可执行”的管理层报告。编辑不改变数字、范围、假设或结论许可；发现冲突时退回总控或对应专业模块。

## 输入检查

先确认项目名称、`scope_id`、阶段、研究截至日期、经营目标、交付状态，以及来源账本、主张账本、假设表、计算底稿和待验证清单。缺失时标明“待补”，不通过润色掩盖缺口。

## 编辑工作流

1. 先写一句话结论，并说明经营目标与适用前提；
2. 提炼不超过两个主矛盾、三个机会和三个风险；
3. 将事实、派生、推断、假设和建议分别标注；
4. 按“证据 → 推导 → 建议 → 前提 → 失效信号”重写关键判断；
5. 把长段落拆成结论卡、表格、行动项和管理层待决策事项；
6. 统一术语、单位、小数位、日期、范围和数字口径；
7. 逐段检查夸大承诺、空泛套话、重复论点和无法兑现的表述；
8. 编辑说明只作为内部附件输出，不得混入最终正文。

## 章节总分原则

每一个章节必须采用“总—分”结构：

1. **开头先给本章最重要结论**：用醒目的章节导语、结论卡或一句话判断直接回答本章要解决的问题；
2. **随后列出重点信息**：通常不超过 3 条，优先放数字、判断、影响和动作；
3. **最后展开细节**：补充证据、公式、来源、假设、案例和限制；
4. **章节结尾给出动作或跳转理由**：说明读者需要决定什么，或为什么值得继续阅读。

读者只看章节标题、导语和重点信息，也应能在最短时间理解本章核心；对结论没有异议时，可以直接跳过后面的证明细节。细节必须服务于核验和决策，不得把关键结论藏在段落末尾、表格脚注或长篇背景中。

## 文案纪律

- 不把 `HYPOTHESIS` 写成事实，不把模型结果写成市场预测；
- 首次出现专业术语时用一句普通话解释；
- 标题表达判断或行动，不用“赋能、引领、焕新”等空泛词；
- 所有金额、面积、套数和比例保留可追溯公式或底稿路径；
- 销售、学位、交通、交付、物业和投资回报承诺须标记审批人；
- 报告已完整交付且通过质检后，不机械追加下一步菜单。

## 精美文案标准

- 每一节先给一个有判断的句子，再给证据和限制；不让读者在资料堆里自行找结论；
- 标题要具体到项目矛盾或决策动作，避免任何项目都能套用的口号；
- 段落有呼吸：短句承接判断，长句解释机制，表格承担重复信息；
- 保留专业克制，但去掉报告腔、套话和无意义的英文标签；
- 重要中文标题手动设计断行，按语义、节奏和阅读停顿断开；
- 每段都通过“删掉后是否损失判断”测试，不能只为显得丰富而保留文字；
- 结尾形成清晰的决策收束，让读者知道现在能决定什么、还不能决定什么。
- 每章首屏都能独立回答“结论是什么、为什么重要、下一步是什么”。

## 输出

默认输出：管理层摘要、正文修订稿、结论/风险/行动卡、图表标题与图注。来源与假设注释、编辑问题清单另存为独立附件，不进入正文。需要模板参照时读取 [editorial-guide.md](references/editorial-guide.md) 和 [github-template-references.md](references/github-template-references.md)。
